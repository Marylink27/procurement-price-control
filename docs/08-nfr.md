# 8. Нефункциональные требования

Каждое требование проверяемое: есть метрика и способ проверки.

## Производительность

| ID | Требование | Проверка |
|---|---|---|
| NFR-01 | Повторный вход в портал без изменений справочников: интерфейс готов к работе не дольше 2 с; справочники (каталог ~10 000 товаров, база ШК, каталоги поставщиков) не загружаются заново | нагрузочный тест, сценарий «вход с прогретым кэшем», 95-й перцентиль |
| NFR-02 | Первый вход или изменение больше 20% справочника: не дольше 8 с на канале 10 Мбит/с | тот же тест с пустым кэшем |
| NFR-03 | Разбор прайса 10 000 строк с сопоставлением и маршрутизацией: не дольше 60 с | тест на файле 10 000 строк |
| NFR-04 | Очередь предложений до 5 000 строк: открытие и сортировка не дольше 1 с | тест API `/offers`, 95-й перцентиль |
| NFR-05 | Одновременно до 30 пользователей без деградации NFR-01...NFR-04 | нагрузочный тест |

**Откуда NFR-01.** В текущей версии портала каждый вход заново загружал три справочника целиком, даже если они не менялись: это главная жалоба пользователей. Решение: версия у каждого справочника (`dictionary_version`), кэш в браузере (IndexedDB), запрос с `If-None-Match`, ответ `304` или только изменённые записи (см. [06-integration-1c.md](06-integration-1c.md), диаграмма I-1).

## Надёжность

| ID | Требование | Проверка |
|---|---|---|
| NFR-06 | Доступность в рабочее время (пн-пт 08:00-20:00 МСК): 99,5% в месяц | мониторинг uptime |
| NFR-07 | Ни одна согласованная цена не теряется при сбое 1С: строки остаются `approved` до подтверждения от 1С | тест с отключением 1С во время выгрузки |
| NFR-08 | Повторная отправка пакета не создаёт дублей цен в 1С | тест повторной отправки с тем же `Idempotency-Key` |
| NFR-09 | Резервная копия БД раз в сутки, хранение 30 дней, восстановление не дольше 4 часов (RPO 24 ч, RTO 4 ч) | учение по восстановлению раз в квартал |

## Безопасность

| ID | Требование |
|---|---|
| NFR-10 | Вход по корпоративной учётной записи (SSO); поставщики по логину и паролю с обязательной второй проверкой по почте |
| NFR-11 | Поставщик видит только свои источники, позиции и предложения; проверка на сервере, а не только в интерфейсе |
| NFR-12 | Все запросы к БД параметризованы; секреты (пароль БД, токен 1С) только в переменных окружения, не в коде и не в репозитории |
| NFR-13 | Загружаемые файлы: только xlsx, xls, csv до 20 МБ, проверка по содержимому, а не по расширению; файлы не исполняются и не отдаются другим пользователям по прямой ссылке |
| NFR-14 | Журнал аудита: кто и когда загрузил прайс, сопоставил, принял решение, изменил пороги; хранение 3 года, без права редактирования |

## Удобство

| ID | Требование |
|---|---|
| NFR-15 | Все сообщения об ошибках на русском и говорят, что сделать: не «Invalid format», а «В строке 9 в колонке "Цена" текст "по запросу": укажите число» |
| NFR-16 | Работа в последних двух версиях Chrome, Яндекс Браузера, Edge; ширина экрана от 1280 px |
| NFR-17 | Основные действия закупщика доступны с клавиатуры: принять, отклонить, следующее предложение |
