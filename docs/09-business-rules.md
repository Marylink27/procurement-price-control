# 9. Бизнес-правила

Правила маршрутизации реализованы и проверены в [`sql/02_business_rules.sql`](../sql/02_business_rules.sql).

## BR-01. Автоматическое сопоставление

Правила применяются по порядку, первое сработавшее побеждает.

| Шаг | Условие | Результат | Уверенность |
|---|---|---|---|
| 0 | у позиции уже есть действующее сопоставление | используется оно | как было |
| 1 | позиция в списке исключённых | статус `excluded` | |
| 2 | ШК позиции есть в базе ШК и ведёт ровно на один активный товар | сопоставление `barcode` | 1,0 |
| 3 | ШК ведёт на несколько товаров | не сопоставлять, пометка «ШК неоднозначен» | |
| 4 | артикул поставщика совпадает с артикулом из ранее подтверждённого сопоставления (смена ШК у поставщика) | сопоставление `article` | 0,95 |
| 5 | схожесть названия (триграммы, после нормализации) не ниже 0,85 и отрыв от второго кандидата не меньше 0,10 | подсказка закупщику с предвыбором | |
| 6 | иначе | `unmatched`, до 3 подсказок по схожести | |

**Нормализация названия:** нижний регистр; `ML`, `мл`, `0,355 л` к одному виду в миллилитрах; удаление слов `CAN`, `ж/б`, `бут.`; ё -> е.

По названию система **не сопоставляет сама** даже при высокой схожести, только предлагает: у напитков вкусы и объёмы отличаются одним словом («Dr Pepper Cherry» и «Dr Pepper Cherry Zero»), и ошибка здесь означает чужую цену в 1С.

## BR-02. Расчёт отклонения

```
отклонение, % = (новая цена - текущая закупочная) / текущая закупочная × 100
```

- Текущая закупочная берётся по паре «товар + этот же поставщик», а не минимальная по всем поставщикам.
- Цены сравниваются за одну единицу товара: если поставщик даёт цену за короб, она делится на кратность из карточки позиции.
- Цены с НДС; если источник без НДС, цена пересчитывается по ставке при импорте.
- Округление до сотых процента.

## BR-03. Маршрут предложения

Пороги задаются по категории, строка `*` действует по умолчанию. Пример настройки:

| Категория | Порог автоприёма | Порог руководителя |
|---|---|---|
| * (по умолчанию) | 3% | 10% |
| Бакалея | 5% | 15% |

Таблица решений:

| Текущая цена | Отклонение | Маршрут |
|---|---|---|
| нет (новая позиция) | | закупщик, затем руководитель |
| есть | снижение или 0 | `approved` автоматически |
| есть | рост ≤ порога автоприёма | `approved` автоматически |
| есть | порог автоприёма < рост ≤ порог руководителя | закупщик |
| есть | рост > порога руководителя | закупщик с обоснованием, затем руководитель |

## BR-04. Решения

- Отказ на любом уровне только с комментарием; комментарий отправляется поставщику.
- Передача руководителю только с обоснованием закупщика.
- Решает только роль, которой принадлежит статус: закупщик по `pending_review`, руководитель по `pending_approval`. Руководитель не может согласовать в обход закупщика.
- Решение необратимо; чтобы пересмотреть цену, поставщик присылает новое предложение.

## BR-05. Конфликты предложений

- Если по позиции пришло новое предложение, а старое ещё ждёт решения, старое закрывается статусом `rejected` с комментарием «Заменено предложением из загрузки N».
- Если `valid_from` в прошлом, она заменяется на дату загрузки + 1 день: задним числом закупочные цены не меняются.
