# 4. User stories и критерии приёмки

Приоритет по MoSCoW. Оценка в story points командой разработки на планировании, здесь не указана.

## Эпик E-1. Загрузка прайсов

### US-01. Загрузка файла · Must

**Как** закупщик, **я хочу** загрузить прайс поставщика файлом, **чтобы** не переносить цены вручную.

```gherkin
Сценарий: Успешная загрузка
  Дано у поставщика "Альфа Импорт" активен источник "Альфа: прайс по почте"
  Когда я загружаю файл "Альфа_прайс_октябрь.xlsx" из 120 строк без ошибок
  Тогда загрузка получает статус "processed"
  И создаются 120 предложений
  И я вижу итог: всего 120, с ошибками 0, сопоставлено N, ждут решения M

Сценарий: Повторная загрузка того же файла
  Дано файл "Альфа_прайс_октябрь.xlsx" уже загружен 01.10 пользователем "Иванова А."
  Когда я загружаю тот же файл повторно
  Тогда загрузка отклоняется
  И я вижу сообщение "Файл уже загружен 01.10 пользователем Иванова А."

Сценарий: Ошибки в отдельных строках
  Дано в файле 100 строк, в 3 из них в колонке цены текст "по запросу"
  Когда я загружаю файл
  Тогда создаются 97 предложений
  И в отчёте об ошибках 3 строки с номером строки, кодом PRICE_NOT_NUMBER и исходным значением

Сценарий: Сдвинутый шаблон
  Дано ошибки распознавания в 40% строк
  Когда я загружаю файл
  Тогда загрузка получает статус "failed"
  И предложения не создаются
  И я вижу подсказку "Проверьте строку заголовка и соответствие колонок в настройках источника"
```

### US-02. Отчёт об ошибках поставщику · Should

**Как** поставщик, **я хочу** получить понятный отчёт об ошибках в файле, **чтобы** исправить его без переписки с закупщиком.

```gherkin
Сценарий: Отчёт по почте
  Дано загрузка завершилась с ошибками в строках
  Когда обработка закончена
  Тогда на адрес источника уходит письмо со списком ошибок
  И к письму приложен исходный файл с подсветкой ошибочных ячеек
```

## Эпик E-2. Сопоставление

### US-03. Автосопоставление по ШК и артикулу · Must

**Как** закупщик, **я хочу**, чтобы позиции с известным ШК или артикулом сопоставлялись сами, **чтобы** вручную разбирать только новые.

```gherkin
Сценарий: Сопоставление по ШК
  Дано в базе ШК есть 0078000082401 у товара "Dr Pepper Cherry 0,355 л ж/б"
  Когда в прайсе приходит позиция с ШК 0078000082401
  Тогда создаётся сопоставление методом "barcode" с уверенностью 1,0

Сценарий: ШК ведёт на два товара
  Дано ШК 4600000000001 привязан к двум товарам каталога
  Когда в прайсе приходит позиция с этим ШК
  Тогда позиция не сопоставляется автоматически
  И попадает закупщику с пометкой "ШК неоднозначен"
```

### US-04. Ручное сопоставление с подсказками · Must

**Как** закупщик, **я хочу** видеть похожие товары каталога для позиции без пары, **чтобы** сопоставить её в один клик.

```gherkin
Сценарий: Подсказки по названию
  Дано позиция "ARIZONA GREEN TEA 680ML" без ШК
  Когда я открываю её в разделе "Сопоставления"
  Тогда я вижу до 3 товаров каталога, отсортированных по схожести названия
  И у каждого процент схожести

Сценарий: Ручное сопоставление запоминается
  Дано я сопоставил "AZ-GT-680" с товаром "Т1-00031001"
  Когда поставщик присылает следующий прайс с артикулом "AZ-GT-680"
  Тогда позиция сопоставляется автоматически по сохранённому сопоставлению
  И не попадает в очередь "Без пары"
```

### US-05. Исключённые позиции · Should

**Как** закупщик, **я хочу** исключить из обработки позиции, которые не являются товаром, **чтобы** они не висели в очереди без пары.

## Эпик E-3. Контроль и согласование

### US-06. Автоприём в пределах порога · Must

**Как** руководитель, **я хочу**, чтобы небольшие изменения принимались без участия людей, **чтобы** команда тратила время только на значимый рост.

```gherkin
Структура сценария: Маршрут по отклонению
  Дано для категории "<категория>" порог автоприёма <авто>% и порог руководителя <рук>%
  И текущая закупочная цена 100 руб
  Когда приходит предложение <цена> руб
  Тогда предложение получает статус "<статус>"

  Примеры:
    | категория | авто | рук | цена | статус           |
    | Напитки   | 3    | 10  | 95   | approved         |
    | Напитки   | 3    | 10  | 103  | approved         |
    | Напитки   | 3    | 10  | 104  | pending_review   |
    | Бакалея   | 5    | 15  | 105  | approved         |
    | Бакалея   | 5    | 15  | 106  | pending_review   |
```

### US-07. Решение закупщика · Must

**Как** закупщик, **я хочу** принять или отклонить предложение с комментарием, **чтобы** решение и его причина сохранились.

```gherkin
Сценарий: Отказ без комментария
  Дано предложение в статусе "pending_review"
  Когда я нажимаю "Отклонить" с пустым комментарием
  Тогда кнопка неактивна и подсказка "Укажите причину, она уйдёт поставщику"

Сценарий: Рост выше порога руководителя
  Дано рост цены 13,75% при пороге руководителя 10%
  Когда я принимаю предложение с обоснованием "Поставщик поднял базовую цену, аналог дороже"
  Тогда статус "pending_approval"
  И руководитель видит предложение в своей очереди с моим обоснованием
```

### US-08. Согласование руководителем · Must

**Как** руководитель, **я хочу** видеть влияние роста цены на маржу, **чтобы** решать не по проценту, а по деньгам.

```gherkin
Сценарий: Карточка согласования
  Дано предложение в статусе "pending_approval"
  Когда я открываю его
  Тогда я вижу текущую и новую цену, отклонение, обоснование закупщика
  И продажи товара за 4 недели в штуках и изменение валовой прибыли в руб при текущей РРЦ
```

## Эпик E-4. Выгрузка в 1С

### US-09. Пакетная выгрузка · Must

**Как** закупщик, **я хочу**, чтобы согласованные цены сами попадали в 1С, **чтобы** не вносить их руками.

```gherkin
Сценарий: Частичная ошибка 1С
  Дано в пакете 5 согласованных предложений
  И одна номенклатура заблокирована в 1С
  Когда 1С возвращает результат
  Тогда 4 предложения в статусе "exported", их цены действуют с даты начала
  И одно в статусе "export_failed" с текстом "Номенклатура заблокирована в 1С"

Сценарий: Повторная отправка
  Дано пакет с ключом идемпотентности K уже загружен в 1С
  Когда из-за таймаута пакет отправляется повторно с ключом K
  Тогда 1С возвращает прежний результат и не создаёт цены второй раз
```

## Эпик E-5. Справочники и сводка

### US-10. Быстрый вход · Must

**Как** закупщик, **я хочу**, чтобы портал открывался быстро, **чтобы** не ждать загрузки справочников при каждом входе.

```gherkin
Сценарий: Справочник не менялся
  Дано справочник товаров у меня закэширован версии 1542
  И на сервере версия 1542
  Когда я вхожу в портал
  Тогда справочник не загружается заново
  И интерфейс готов к работе за 2 секунды

Сценарий: Справочник изменился
  Дано у меня версия 1542, на сервере 1550
  Когда я вхожу в портал
  Тогда загружаются только записи, изменённые после версии 1542
```

### US-11. Сводка · Should

**Как** руководитель, **я хочу** видеть по каждому поставщику, сколько предложений без пары, ждут решения и выгружено, **чтобы** находить узкие места.
